EP capture

Pulls the raw, still-encrypted octets of a call off a RadioFoundry radio running the EP capture build (CONFIG_EP_CAPTURE), so the recipe can be worked out later on another computer. Runs entirely in this tab — nothing is uploaded anywhere.

This browser doesn't support Web Serial, so it can't talk to the radio. Please open this page in Chrome or Edge on a computer (not a phone) instead.

1. Connect

  1. Plug the radio into this computer with its programming cable, and power it on.
  2. Click Connect below and pick the radio's port from the list the browser shows.
not connected

2. Capture

  1. Click Start capture.
  2. Have the encrypted call come in (or key it up) now — this page only sees calls while capture is running.
  3. Watch the count go up below. A few PI headers and a few dozen voice bursts is plenty.
  4. Click Stop & save and send the file it downloads.
off

The ring filled up and dropped some frames — the oldest ones are kept, so this is fine as long as you captured a PI header near the start of the call. If the count below looks short, try again from the start of a call.

#slotkindcrcbytes
Advanced: quick keystream check (optional, for whoever analyzes the capture)

This does not decrypt anything by itself — the exact recipe (how the key and the IV combine, how many keystream bytes are discarded, and where the IV sits in the voice bits) is what the capture is for figuring out. This just runs RC4 for you against a captured entry's raw bytes at a few candidate starting offsets, so someone comparing it against known-clear reference bytes doesn't have to do the XOR by hand.
