# P25 Phase 1

Receive side of APCO Project 25 Phase 1 (C4FM, 12.5 kHz, 4800 baud). What exists is the front end: finding frames in
FM receive audio and reading each one's network access code (NAC) and data unit ID (DUID). Control channel blocks,
voice and transmit are not written.

Code: `core/p25` (portable, no RTOS, no board), host test `tests/host/p25Test.c`. Build switch: `CONFIG_P25`
(`docs/build-config.md`). Nothing feeds it audio yet; which boards can is in [feature-matrix.md](../feature-matrix.md).

Sources (public, read for the formats only; no implementation was used, `CLEANROOM.md`): TIA-102.BAAA (Common Air
Interface) for the frame sync, the dibit symbol mapping, the NID and the status symbols; BCH code theory for the NID
code (derived and checked, see 2.2).

## 1. Signal

| Item | Value |
|---|---|
| Symbol rate | 4800 baud, 2 bits per symbol (a dibit) |
| Dibit to level | 01 = +3, 00 = +1, 10 = -1, 11 = -3 (the same as the ETSI 4FSK mapping the DMR chips use) |
| Frame sync | 48 bits, 0x5575F5FF77FF: 24 dibits, every one an outer level |
| Status symbol | every 36th dibit counted from the first sync dibit (not yet confirmed on air) |

## 2. Frame start

### 2.1 Layout

A frame starts with the 24 sync dibits, then the 32-dibit NID, with a status symbol inserted at its 36th position, so
the NID's 11th and 12th dibits have a status symbol between them. The NID is 64 bits:

| Bits | Content |
|---|---|
| 63..52 | NAC, 12 bits |
| 51..48 | DUID, 4 bits |
| 47..1 | BCH parity, 47 bits |
| 0 | parity bit, chosen so the 64-bit weight is even (not yet confirmed on air; the decoder ignores it) |

| DUID | Frame |
|---|---|
| 0x0 | header data unit |
| 0x3 | terminator without link control |
| 0x5 | logical link data unit 1 (voice) |
| 0x7 | trunking signaling data unit (control channel TSBKs) |
| 0xA | logical link data unit 2 (voice) |
| 0xC | packet data unit |
| 0xF | terminator with link control |

### 2.2 NID code

The 63 bit word (NAC and DUID, 16 data bits) is a narrow-sense BCH code over GF(64) built on x^6 + x + 1, with roots
alpha^1 to alpha^22. Its generator has degree 47 (octal 6331141367235453) and the minimum distance is 23, so up to 11
bit errors are corrected. The decoder tries every one of the 65536 codewords in Gray code order, which costs one XOR
and one popcount per word, and takes the nearest. A word is accepted when it is within 11 bits and its DUID is one of
the table's.

## 3. Receiver front end

Input is the FM demodulator's audio at any rate from 7200 to 48000 Hz, 16 bit signed, integer math only.

1. The signal is read at 8 timing phases per symbol with a cubic (Catmull-Rom) interpolator, so no clock recovery
   loop is needed: every frame carries its own sync.
2. Each phase's last 24 values are fitted to the sync's pattern, `v = offset + scale * s` with s = +1 / -1. The sync
   is not balanced, so the offset is fitted with the scale, not taken as a mean. The score is 1 minus the mean
   residual over the scale; 0.75 or more is a hit, and the best phase at that moment is kept for the frame.
3. The next 33 dibits are sliced at +-2/3 of the fitted scale around the fitted offset, the status symbol is
   dropped, and the 32 NID dibits are decoded.
4. The callback gets the NAC, DUID, the sample count, the fit score, and the offset and scale. The offset is a
   transmit frequency error; the scale is the deviation.

The host test sends frames through a raised cosine shaped signal and checks every timing offset, six sample rates, a
DC offset of +-5000 counts, a signal 12 times weaker, 14 dB signal to noise, and noise alone (no frames).

## 4. Limits and next steps

- The audio comes from the FM demodulator, which has its own filtering; how well that suits C4FM is measured on air.
- The status symbol position and the NID parity bit are from the standard but unconfirmed against a real signal.
- Control channel decode needs the rate 1/2 trellis code and the data interleave of the standard, and the 16 bit CRC.
  Those tables are not in the tree yet. A capture's CRCs check them.
- Voice needs an IMBE vocoder, which has no source that fits the clean room rules yet.
